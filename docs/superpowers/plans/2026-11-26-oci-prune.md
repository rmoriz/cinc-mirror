# Retention Prune Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete every OCI publication a policy no longer marks for mirroring, on ordinary registries through the distribution API and on GHCR through the GitHub Packages API.

**Architecture:** A crawl-derived wanted set per project is reconciled against what the target lists, minus a protection set (open incidents, `-superseded` archive tags, wanted publications' remote digests, anything newer than the cutoff). `src/prune.rs` owns the set logic and two thin backends list and delete. A pruned publication becomes a ledger state so `verify` skips it and `repair` leaves it alone unless asked.

**Tech Stack:** Rust 2021, tokio, reqwest, axum (test mocks only), rusqlite, clap.

**Spec:** `docs/superpowers/specs/2026-11-26-oci-prune-design.md`

## Global Constraints

- MSRV and lint gate are the repository's: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` must pass before every commit.
- Every public item carries a `///` doc comment; every fallible public function a `# Errors` section. Module docs sit at the top of each new file.
- No `unwrap`/`expect` outside tests and `main` wiring; no `panic!` on remote data.
- `Summary::finish` stays the only exit-code authority for publish runs. Prune counts never change a publish run's exit code.
- Only tag names decide reconciliation. Digests are used only to protect untagged versions.
- Prune never leaves the crawl scope of the run.
- `[retention] prune` defaults to `false`; `mirror.ci.toml` is the only place it is `true`.
- Commit messages carry no `Co-Authored-By` trailer.

## Review Focus

1. A stale tag with no ledger row must still be deleted, and must not break the `publications.artifact_key` foreign key on replay.
2. A wanted tag that the ledger qualified with a digest (`tag_override`) must survive the prune.
3. A registry that answers `405` to `DELETE` must be reported once and skipped, not consume the deletion budget.
4. A push that lands while the run is crawling must survive the prune (cutoff after the crawl, before listing).
5. A package that is not linked to the repository answers `403`; the pruner must stop that package with one warning instead of burning the remaining budget.
